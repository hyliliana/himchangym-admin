# 힘찬짐 운영 관리자

운영자·트레이너용 Next.js 앱입니다. 마스터 관리자와 부운영자(데스크)가 회원, 이용권 구매 기록, 트레이너, 예약을 관리합니다. 운영 계정 관리는 마스터 관리자에게만 제공하며 최종 접근 권한과 데이터 검증은 백엔드에서 강제합니다.

## 로컬 실행

Node.js 20.9 이상과 pnpm이 필요합니다.

```sh
pnpm install
cp .env.example .env.local
pnpm dev
```

`http://localhost:3101`을 엽니다. `BACKEND_URL`은 서버 전용 환경 변수이며 예시는 `http://localhost:4100`입니다. 초기 관리자 계정은 백엔드 운영자가 별도로 설정합니다. 비밀번호를 코드나 문서에 기록하지 않습니다.

## 구현 범위

- 직원 로그인·로그아웃, 임시 비밀번호 로그인 시 비밀번호 변경 강제
- 회원·오늘 예약·처리 대기 예약 집계, 14일 이내 만료·잔여 이용권, 이번 달 트레이너 완료 수업
- 예약일·상태 필터, 예약에서 완료·노쇼·취소 전환, 완료 수업의 PT 피드백 작성·수정
- 이름·연락처 뒷자리 회원 검색, 회원 등록 및 이름·연락처·가입일 수정, 삭제·복원
- 회원별 이용권 구매 기록 입력과 조회: 종류, 구매일, 실결제액, 선택 만료일
- 구매 내역별 영수증 이미지 첨부·조회·확대: JPG/PNG/WebP, 파일당 2MB 이하, 구매별 총 3,000,000바이트 이하·최대 5개
- 트레이너 등록·이름·근무요일 수정·삭제·복원, 이용권 종류 등록·수정·삭제·복원
- 관리자 전용 직원 생성·권한/활성 상태 수정·비밀번호 초기화

구매 기록은 데스크에서 확인한 현장 결제의 기록이며 PG 결제 기능은 없습니다. 영수증은 이미지 보관과 열람만 제공하며 OCR 자동 추출·삭제는 포함하지 않습니다. 이용권 총 횟수는 10/20/30회입니다. 근무요일은 일요일 0부터 토요일 6까지 사용합니다. 표시 날짜와 시각은 한국 시간 기준입니다.

## 인증과 안전

브라우저는 같은 출처 `/api/[...path]`만 호출합니다. Route Handler가 `gym_session` HttpOnly·SameSite=Lax 쿠키를 백엔드 Bearer 인증으로 변환합니다. 운영에서는 Secure 쿠키를 사용하므로 HTTPS가 필요합니다. 로그인 응답의 토큰을 브라우저 JSON에서 제거하고 서버 로그에 남기지 않습니다. 비밀번호나 세션 토큰을 localStorage에 저장하지 않습니다.

직원 생성·비밀번호 초기화와 회원 등록으로 발급된 임시 비밀번호는 화면 메모리에만 잠깐 유지하며 별도로 저장하지 않습니다. 최초 로그인 후 비밀번호 변경을 강제하며, 초기 변경 전에는 운영 기능에 접근할 수 없습니다. 임시 비밀번호와 자격정보는 스크린샷이나 운영 로그로 수집하지 않아야 합니다. 회원 등록의 일회성 암호 안내와 닫기 정책은 아래에 설명합니다.

관리자 메뉴 숨김은 사용성을 위한 처리입니다. 백엔드가 역할, 비활성 계정, 마지막 관리자 보호, 예약 상태 전환 및 잔여 횟수를 검증합니다. 사용자가 완료·노쇼·취소 또는 계정 비활성화를 선택하면 확인 후 요청합니다.

## 검증 상태와 실행·배포 안내

현재 변경에서 확인한 결과는 production build와 TypeScript 검사 통과입니다. `pnpm build` 및 `pnpm typecheck`를 확인했습니다. 회원·트레이너·이용권 종류의 삭제·복원에 대한 실제 API 통합검증, 브라우저 UX 검수와 이번 변경의 배포는 아직 완료로 표시하지 않습니다.

아래 명령은 검증과 실행 방법이며, 이 문서의 실행·배포 완료 보고가 아닙니다.

```sh
pnpm build
pnpm typecheck
pnpm start
```

Vercel에서 프로젝트 루트를 이 폴더로 설정하고 서버 환경 변수 `BACKEND_URL`에 HTTPS 백엔드 주소를 등록합니다. `NEXT_PUBLIC_` 변수로 설정하지 않습니다. 백엔드 환경 설정과 DB는 이 저장소에 포함하지 않습니다. 디자인 기준은 이 저장소의 `DESIGN.md`의 직방(ZUIX) 카탈로그의 주황·회색 팔레트와 Pretendard, 4px 모서리, 상태 표현입니다.


## 승인 디자인 통합

제출 당시 `chief/himchangym-admin`의 `ffca914`를 보존하고 `chief/himchangym-design-update`에서 승인된 디자인을 통합했습니다. 원본 기준은 `DESIGN.md`, 적용·보정과 검수 범위는 `DESIGN-APPLICATION.md`에 기록합니다. 기존 구매·예약·권한·영수증 API는 변경하지 않습니다.

디자인 카탈로그 출처: [ko-design-md by ChangSik Yoon](https://github.com/CaesiumY/ko-design-md), [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). 카탈로그 원문은 `LICENSE-DESIGN-CONTENT` 적용 범위를 따릅니다. Pretendard 1.3.9는 SIL OFL 1.1이며 `LICENSE-PRETENDARD`를 보존합니다. H 덤벨 SVG는 힘찬짐 전용 심볼이며 외부 브랜드 로고를 사용하지 않습니다.

## 회원·트레이너·이용권 종류의 등록·수정·삭제·복원

`chief/entity-lifecycle`에서 기존 승인 디자인과 기능을 유지하며 운영 항목 관리를 확장합니다. 삭제는 `deletedAt`을 기록하는 소프트 삭제입니다. 기본 목록은 활성 항목이며, ‘삭제된 항목’ 또는 ‘전체 항목’에서 삭제 상태와 복원 버튼을 확인할 수 있습니다. 삭제 상태에서는 수정할 수 없으며 먼저 복원해야 합니다. 삭제는 과거 업무 기록을 지우는 동작이 아닙니다.

- 회원 등록: 이름·연락처·로그인 이메일·선택 가입일. 서버가 발급한 임시 비밀번호는 생성 직후 화면에서 한 번만 보여 주고 별도로 저장하거나 기록하지 않습니다. 회원은 최초 로그인 때 변경해야 합니다.
- 회원 수정: 이름·연락처·선택 가입일. 미래 가입일은 허용하지 않습니다.
- 삭제 회원: 로그인 차단·기존 세션 종료와 신규 구매 차단을 확인창에 안내하고, 기존 구매 내역·영수증 조회는 유지합니다. 복원 후에는 다시 로그인해야 합니다.
- 회원·트레이너: 과거·미래와 관계없이 처리 대기(`booked`) 예약이 한 건이라도 남아 있으면 서버가 삭제를 HTTP 409로 거절합니다. 먼저 예약 상태를 정리해야 하며, 확인 대화상자는 오류를 표시하고 열린 상태를 유지합니다.
- 트레이너: 삭제 후 신규 예약의 트레이너 선택에서 제외합니다. 과거 수업 기록은 보존하며 복원하면 신규 예약 대상에 다시 포함합니다.
- 이용권 종류: 삭제 후 새 구매 대상에서 제외하고, 이미 구매한 회원 이용권의 횟수·만료일·구매 및 예약 기록은 유지합니다. 복원하면 새 구매 대상으로 다시 사용할 수 있습니다.
- 삭제·복원 대화상자: 대상 이름과 영향을 표시하고 ‘취소’에 최초 포커스를 둡니다. 처리 중 중복 요청·닫기·Escape를 막고 완료/취소 후 원래 버튼이나 목록 필터로 포커스를 돌려줍니다.
- 예약 표와 완료 수업 메모의 사용자 표시 이름은 ‘PT 피드백’입니다. 서버 필드 `note`와 저장 조건은 유지합니다.

추가 계약:

- 회원 등록: `POST /admin/members` → `{member, temporaryPassword}`
- 회원 관리 목록: `GET /admin/members?q=&includeDeleted=true`
- 트레이너·이용권 종류 관리 목록: `GET /admin/catalog?includeDeleted=true`
- 삭제: `DELETE /admin/members/:id`, `/admin/trainers/:id`, `/admin/pass-types/:id`
- 복원: `POST /admin/members/:id/restore`, `/admin/trainers/:id/restore`, `/admin/pass-types/:id/restore`

`includeDeleted=true`는 활성·삭제 항목을 모두 반환하며 화면에서 활성·삭제·전체를 구분합니다. 이를 생략한 기본 조회와 구매·예약 선택용 `GET /catalog`는 활성 항목만 제공합니다. 삭제된 회원의 과거 구매·영수증은 직원이 계속 조회할 수 있습니다. BFF는 DELETE를 지원하며 기존 HttpOnly 인증·Origin 검사·token 제거를 유지합니다.

회원 등록·수정 요청 중에는 모달의 닫기·Escape·취소를 막습니다. 신규 등록의 일회성 임시 비밀번호 결과창은 ‘확인했어요’ 버튼으로만 닫아 응답을 확인하기 전에 화면을 이탈하지 않도록 합니다.

## 트레이너 전용 화면

- 경로: `/trainer` (관리자 로그인 화면 하단에서도 이동 가능).
- 관리자 `트레이너` 목록에서 로그인 계정을 만들면 임시 비밀번호를 한 번 표시합니다. 생성·비밀번호 초기화는 관리자만 할 수 있습니다.
- 트레이너는 첫 로그인 후 비밀번호를 변경하고, 본인 예약의 승인·거절, 승인된 수업의 완료·노쇼, 완료 수업의 PT 피드백을 처리합니다.
- 화면은 한국 시간으로 표시합니다. 승인·거절 시 조회 당시 예약 시간을 함께 보내므로, 회원이 일정을 바꿨다면 최신 일정을 다시 확인해야 합니다.
- 관리자 `/api`는 `gym_session`, 트레이너 `/trainer-api`는 `gym_trainer_session` HttpOnly 쿠키를 사용합니다. 트레이너 쿠키 범위는 `/trainer-api`로 제한하며, 로그인·로그아웃이 관리자 세션에 영향을 주지 않습니다.
- `/trainer-api`는 트레이너 인증과 본인 예약 경로만 전달합니다. 로그인 유형은 서버에서 `trainer`로 고정하고 JSON 응답의 토큰을 제거합니다.
- 직원 예약 화면은 승인 대기·예약 확정·승인 거절을 구분하며, 승인 대기 예약의 완료·노쇼를 막습니다.

## 화면의 네 가지 역할

회원은 회원 앱에서 자신의 이용권·예약·피드백을 확인하고, 트레이너는 이 앱의 `/trainer`에서 담당 수업을 처리합니다. 마스터 관리자는 운영 계정 관리까지 포함한 전체 운영을 맡고, 부운영자(데스크)는 회원·이용권·예약 등의 데스크 업무를 맡습니다. 운영 로그인과 사이드바, `운영 계정` 메뉴에서 이 이름을 표시합니다. 내부 권한값 `staff/admin`, `staff/employee`, `trainer`, `member`와 서버의 권한 검증은 그대로 유지합니다.
